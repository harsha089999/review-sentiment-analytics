# Customer Review Sentiment Analytics

[![Run project](https://github.com/harsha089999/review-sentiment-analytics/actions/workflows/run.yml/badge.svg)](https://github.com/harsha089999/review-sentiment-analytics/actions/workflows/run.yml)

**Classify review sentiment, find what customers complain about and roll it up by store and month for a dashboard.**

> **About the data:** everything in this repo is simulated, generated by the code with a fixed random seed so results are reproducible. The numbers describe the simulation, not the real world. Each project says how to swap in a real dataset.

## The business question

What are customers actually complaining about, and is it improving or getting worse at each store?

## What this project does

Star ratings say something is wrong but not what. This project classifies review sentiment, discovers themes in the negative reviews and turns the text into numbers a BI dashboard can trend.

## The data

3,000 template-generated reviews: 6 positive and 12 negative phrases across four themes (delivery, freshness, price, staff), 4 stores named after Canterbury suburbs (not real business data), January to September 2026. The Hornby store is built to get worse from June 2026, with more negative reviews and a heavy delivery-complaint share.

## How it works

1. TF-IDF features (single words and word pairs) and a logistic regression classifier on a 75/25 stratified split.
2. Predict sentiment for every review.
3. For predicted-negative reviews, build TF-IDF again with generic filler words removed and run NMF topic modelling (4 topics). Assign each review to its strongest topic and list each topic's top terms.
4. Aggregate by store and month: review count, percent negative and the most common topic.

## Run it

```bash
git clone https://github.com/harsha089999/review-sentiment-analytics
cd review-sentiment-analytics
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python src/main.py
```

It runs in about 15 seconds or less on a laptop and writes its files to `outputs/`. Python 3.10 or newer is recommended.

## Limitations and honest caveats

- Perfect accuracy is a sign the data is too easy. Use a real dataset before quoting any score.
- Topic numbers are not named automatically. Labels come from reading the top terms.
- Only English, no sarcasm, no mixed sentiment, no te reo Maori.

## Using real data

Use the Amazon Fine Food Reviews or Yelp Open Dataset from Kaggle (or your own reviews, with permission). Map columns to `store, month, text, label` in place of `make_data()`.

## Turning it into a dashboard

Percent negative over time by store, a top-complaint-themes bar chart, and a table of example reviews per theme.

## Ideas to extend it

- Fine-tune a small transformer (for example DistilBERT) and compare accuracy and cost.
- Have an LLM write a weekly summary from the aggregated numbers.
- Test on te reo Maori and mixed-language reviews.
